# Design: Prompt Composer CLI (`agenticenti`)

Date: 2026-02-20
Status: Accepted

## Overview

A Rust binary that composes agent prompts from modular pieces: one base role + one or more language/stack overlays + optional testing mode overlay. Prompts are embedded at compile time for zero-dependency distribution, with a runtime override directory (`$HOME/.agenticenti/`) for user customization.

Based on the composable agent prompt system designed in `agent-prompts.md`:
`Final Prompt = Base Role + Language/Stack Overlay + Project Context`

## Architecture

```
                    ┌─────────────────────────────────┐
                    │     agenticenti CLI (Rust)       │
                    │                                  │
 User runs:        │  1. Parse args (clap)            │
 agenticenti       │  2. For each piece:              │
   compose         │     a. Check $HOME/.agenticenti/ │
   coder           │     b. If override exists → use  │
   rust python     │     c. Else → use embedded       │
                    │  3. Concatenate with ---         │
                    │  4. Print to stdout              │
                    └─────────────────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
     ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
     │ Embedded     │ │ Embedded     │ │ Embedded     │
     │ Roles (15)   │ │ Overlays (7) │ │ Test Modes(2)│
     │ (build.rs)   │ │ (build.rs)   │ │ (build.rs)   │
     └──────────────┘ └──────────────┘ └──────────────┘
```

### Runtime override directory

```
$HOME/.agenticenti/                   # Default, overridable via --config-dir
├── roles/
│   └── coder.md                      # Full replacement of embedded coder.md
├── overlays/
│   └── rust.md                       # Full replacement of embedded rust overlay
└── testing-modes/
    └── e2e.md                        # Full replacement of embedded e2e overlay
```

**Resolution logic:** For each requested prompt piece, check the config directory first. If a file exists there with the matching path, use it as a full replacement (no merging). Otherwise, use the embedded compile-time default. Users can also add entirely new roles/overlays that don't exist in the embedded set.

## CLI Interface

### Subcommands

```
agenticenti compose <role> [languages...] [--testing-mode <mode>] [--config-dir <path>]
agenticenti list [--roles | --overlays | --testing-modes] [--config-dir <path>]
```

### Examples

```bash
# Single role + single language
agenticenti compose coder rust

# Single role + multiple languages (multi-stack project)
agenticenti compose coder rust typescript-node

# Role with testing mode overlay
agenticenti compose tester --testing-mode unit rust

# Role with testing mode + multiple languages
agenticenti compose tester --testing-mode e2e python terraform

# Team leader (no language overlay needed)
agenticenti compose team-leader

# List all available roles (embedded + overrides)
agenticenti list --roles

# List all available overlays
agenticenti list --overlays

# Use a custom config directory
agenticenti --config-dir /path/to/overrides compose coder rust
```

### Output

Raw composed markdown to stdout. Composition order:

```
[Base Role Prompt]

---

[Language Overlay 1]

---

[Language Overlay 2 (if multi-stack)]

---

[Testing Mode Overlay (if tester role + --testing-mode)]
```

**Exit codes:** 0 = success, 1 = unknown role/overlay, 2 = invalid arguments.

## Rust Implementation

### Dependencies

- `clap` (with derive feature) — CLI argument parsing
- No other runtime dependencies. Pure string composition.

### build.rs — Compile-time discovery

The build script:
1. Walks `prompts/roles/`, `prompts/overlays/`, `prompts/testing-modes/`
2. For each `.md` file found, generates an `include_str!` constant
3. Generates lookup functions: `embedded_role(name) -> Option<&'static str>`, etc.
4. Generates name lists: `all_role_names() -> &'static [&'static str]`, etc.
5. Outputs to `src/generated/prompts.rs`

Adding a new role or overlay = adding a `.md` file and recompiling. No Rust code changes needed.

### composer.rs — Resolution + composition

```rust
// Pseudocode

fn resolve_prompt(config_dir: &Path, category: &str, name: &str) -> Result<String> {
    let override_path = config_dir.join(category).join(format!("{name}.md"));
    if override_path.exists() {
        Ok(fs::read_to_string(override_path)?)
    } else {
        embedded_lookup(category, name)
            .map(|s| s.to_string())
            .ok_or_else(|| Error::UnknownPrompt { category, name })
    }
}

fn compose(role: &str, languages: &[String], testing_mode: Option<&str>, config_dir: &Path) -> Result<String> {
    let mut parts = vec![resolve_prompt(config_dir, "roles", role)?];

    for lang in languages {
        parts.push(resolve_prompt(config_dir, "overlays", lang)?);
    }

    if let Some(mode) = testing_mode {
        parts.push(resolve_prompt(config_dir, "testing-modes", mode)?);
    }

    Ok(parts.join("\n\n---\n\n"))
}
```

### main.rs — CLI entry point

Uses clap derive macros with two subcommands:

- `Compose { role: String, languages: Vec<String>, testing_mode: Option<String> }`
- `List { roles: bool, overlays: bool, testing_modes: bool }`

Global option: `--config-dir` defaulting to `$HOME/.agenticenti`.

The `list` subcommand merges embedded names with any additional `.md` files found in the config directory, indicating which are overridden vs. default vs. user-only.

### New role: evangelist

A developer advocacy and technical communication role. Responsibilities:
- Write blog posts, talks, tutorials, and demos that showcase the project
- Translate internal technical decisions into compelling external narratives
- Create sample applications and starter templates
- Write developer-facing documentation (getting started guides, migration guides)
- Produce changelog summaries and release announcements
- Access: Read-only across repo + web search + write to `docs/evangelism/`
- Model tier: Sonnet (writing benefits from speed + quality balance)

A GitHub Actions CI/CD specialist role. Responsibilities:
- Author, optimize, and maintain GitHub Actions workflows

- Create reusable workflows and composite actions
- Ensure supply chain security (pinned SHAs, minimal permissions)
- Access: Read/write `.github/` files. Read-only access to source code + docs.
- Model tier: Sonnet (CI/CD changes benefit from speed, with human review gates)

### New language overlays (2)

**bash** — covering:
- `set -euo pipefail` as mandatory header
- ShellCheck as strict linter
- Quoting discipline (`"${var}"` always)
- Error handling (trap, exit codes, error functions)
- POSIX vs. bash-specific feature guidance
- Testing with `bats` (Bash Automated Testing System)
- Anti-patterns: no `eval`, no unquoted globs, no parsing `ls`

**docker** — covering:
- Multi-stage builds as default pattern
- Minimal base images (distroless/alpine preference)
- Layer ordering for cache efficiency
- Security: non-root USER, no secrets in build args/layers, `.dockerignore`
- Health checks, signal handling (exec form ENTRYPOINT)
- `hadolint` as linter
- Anti-patterns: no `latest` tag, no `apt-get upgrade` without pinning

### Research approach

For each prompt (roles and overlays), research the top open-source agent frameworks cited in the original document (OpenHands, Claude Code, aider, wshobson/agents, everything-claude-code, Shippie) to find the strongest patterns. The existing prompts are already well-researched — the main work is:

1. Verify and strengthen existing prompts against latest patterns
2. Create the bash and docker overlays from best practices
3. Create the software-evangelist role from developer advocacy research
4. Ensure all overlays are comprehensive and role-agnostic

## Testing Strategy

- **Unit tests:** Verify composition logic (correct concatenation, override resolution, error handling for unknown names)
- **Integration tests:** Build the binary, run it with known inputs, assert stdout matches expected composed prompts
- **E2E test:** Full `cargo build && ./target/debug/agenticenti compose coder rust` and verify output

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| build.rs path handling across platforms | Medium | High | Use `std::path::Path` consistently, test on Linux |
| Generated file conflicts with IDE | Low | Low | Gitignore `src/generated/`, add "do not edit" header |
| Override directory not found | Low | Low | Gracefully skip if `$HOME/.agenticenti` doesn't exist |
| Prompt files too large for `include_str!` | Very Low | Medium | Current largest is ~15KB, well within limits |

## Out of Scope

- Project context injection (the third part of the composition formula — left to the caller)
- Prompt versioning or changelog tracking
- Interactive TUI for prompt selection
- Remote prompt fetching or sync
- Prompt validation or linting
